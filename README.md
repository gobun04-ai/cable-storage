# 케이블노트

현장에서 공사 케이블 물량과 장비 목록을 정리하고, 텍스트와 엑셀로 공유하는 휴대폰용 웹앱(PWA)이다.

노트에 적던 방식 — 케이블 종류, 시작점(From), 종단(To), 물량(`2+3+5+10`), 교체·신규 장비 — 을 그대로 입력하면
합계를 계산하고 규격별로 집계해 준다.

## 특징

- **통신이 끊긴 곳에서도 동작한다.** 지하·전기실에서 쓰기 위해 모든 데이터를 휴대폰 안에 저장한다.
- **항목을 깊이 제한 없이 중첩**할 수 있다. 공사 > 1층 전기실 > MCC반 > A구역 부하 …
- **물량은 적은 그대로 저장하고 합계를 자동 계산**한다. `2+3+5+10+5+3+2` → 30 m. 나중에 검산할 수 있게 수식 원문을 남긴다.
- **물량 전용 키패드**를 띄운다. 숫자와 사칙연산·괄호만 있어 한 손으로 빠르게 입력할 수 있다.
- **이전에 쓴 값을 제안**한다. 다른 공사에서 쓰던 케이블 종류도 새 공사에서 그대로 꺼내 쓸 수 있다.
- 정리 결과를 **카카오톡에 붙여 넣을 텍스트**와 **견적용 엑셀(3시트)** 로 내보낸다.

## 필요한 것

- Node.js 20 이상
- 최신 크롬 계열 브라우저 (안드로이드 크롬 기준으로 만들었다)

## 명령

| 명령 | 하는 일 |
|---|---|
| `npm install` | 의존성 설치 |
| `npm run dev` | 개발 서버 실행. 같은 와이파이의 휴대폰에서도 열린다 |
| `npm test` | 단위 테스트 실행 |
| `npm run test:watch` | 파일을 고칠 때마다 테스트 재실행 |
| `npm run typecheck` | 타입 검사만 실행 |
| `npm run build` | 타입 검사 후 `dist/` 에 배포본 생성 |
| `npm run preview` | 만들어진 배포본을 로컬에서 확인 |
| `npm run icons` | 앱 아이콘(PNG) 다시 생성. 디자인을 바꿀 때만 쓴다 |

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `VITE_BASE` | `/` | 앱이 놓일 경로. GitHub Pages 처럼 하위 경로로 서비스할 때 `/저장소이름/` 을 넘긴다 |

예: `VITE_BASE=/cable-route/ npm run build`

시크릿(API 키·토큰)은 쓰지 않는다. 이 앱은 서버와 통신하지 않는다.

## 폴더 구조

```
public/          아이콘 등 그대로 복사되는 파일
scripts/         아이콘 생성 스크립트
src/
  types.ts       데이터 모델 (저장 형식과 백업 형식의 기준)
  lib/           화면과 무관한 순수 로직 — 테스트가 붙어 있는 곳
    db.ts          IndexedDB 저장소
    tree.ts        항목 트리 조립·번호 매기기·이동
    records.ts     케이블·장비 기록 추가/수정/삭제
    expr.ts        물량 수식 계산기
    summary.ts     규격별 집계
    exportText.ts  공유 텍스트 생성
    exportXlsx.ts  엑셀 생성
    backup.ts      JSON 백업·복원
  components/    화면 조각
  screens/       화면 (목록 / 공사 / 정리·공유 / 설정)
  state/         전역 상태 (설정, 알림)
  styles/        디자인 토큰과 전역 스타일
```

## 데이터가 저장되는 곳

브라우저의 IndexedDB 에 저장된다. **서버로 보내지 않는다.**

그래서 아래 경우에 데이터가 사라진다.

- 브라우저의 사이트 데이터를 지웠을 때
- 저장 공간이 부족해 브라우저가 정리했을 때 (설정 화면의 `자동 삭제 방지 요청`으로 확률을 낮출 수 있다)
- 휴대폰을 바꿨을 때

**중요한 공사는 끝난 뒤 설정 화면에서 백업 파일을 받아 두거나, 정리 내용을 공유해 남겨 두는 것이 안전하다.**

기록을 비우고 싶을 때는 설정 화면의 `모든 데이터 삭제`를 쓴다. 브라우저 설정에서 사이트 데이터를 지우는 방법도 있지만,
같은 브라우저의 다른 사이트까지 영향을 받기 쉬워 앱 안에 따로 두었다.

## 배포

`main` 브랜치에 push 하면 GitHub Actions 가 타입 검사 → 테스트 → 빌드 → 배포를 자동으로 한다.
설정은 [.github/workflows/deploy.yml](.github/workflows/deploy.yml) 에 있다.

- 저장소: https://github.com/gobun04-ai/cable-storage
- 주소: https://gobun04-ai.github.io/cable-storage/

처음 한 번은 저장소의 **Settings → Pages → Source** 를 `GitHub Actions` 로 지정해야 한다.

하위 경로(`/cable-storage/`)는 워크플로가 저장소 이름을 읽어 자동으로 넣는다. 저장소 이름을 바꿔도 따라간다.

배포본을 로컬에서 미리 보려면:

```bash
$env:VITE_BASE="/cable-storage/"; npm run build   # PowerShell
npm run preview
```

PWA 로 설치하려면 **HTTPS 가 필요하다.** GitHub Pages 는 기본으로 HTTPS 를 제공한다.
개발 서버를 휴대폰에서 열면(사내망 IP, HTTP) 화면은 보이지만 설치와 오프라인은 동작하지 않는다.
